PART 1: THE PLUGIN ARCHITECTURE & EXPANSIBILITY
--------------------------------------------------------------------------------

Q1: "How exactly do you handle plugin discovery? If I want to add a 'Time-Series' 
    plugin tomorrow, where does the code go and how does the CLI find it?"

A: The framework uses a 'PluginRegistry' system (mlcli/plugins/registry.py). Each 
   plugin must inherit from the 'PluginBase' class. To add a new one, you simply:
   1. Create a new folder in 'mlcli/plugins/'.
   2. Implement the 'get_directory_structure()' and 'get_boilerplate_files()' methods.
   3. The registry automatically discovers any class that inherits 'PluginBase' 
      using Python reflection/subclassing, making it truly 'plug-and-play'.

Q2: "Your 'init' command generates a lot of files. How do you ensure consistency 
    across different OS environments (Windows/Linux/Mac)?"

A: We use Python's 'pathlib' library throughout the core. Unlike old-school 
   string-based paths, 'pathlib' handles slash direction and OS-specific 
   filesystem quirks automatically, ensuring the generated projects are portable.

--------------------------------------------------------------------------------
PART 2: DATA ENGINEERING & PREPROCESSING ROBUSTNESS
--------------------------------------------------------------------------------

Q3: "The 'preprocess' command cleans data, but the 'predict' command often fails 
    in ML projects because the 'unseen' data doesn't match the 'training' data. 
    How did you solve this 'Feature Alignment' problem?"

A: This is the core of our technical fix. We don't just save a 'data_profile.json'. 
   We use Scikit-Learn's 'ColumnTransformer' and 'Pipeline'. During 'preprocess', 
   we save the FITTED preprocessor object as 'preprocessor.pkl'. 
   In 'predict', we reload this exact object. This ensures that if 'Age' was 
   scaled by a Factor of 10 during training, it is scaled by the SAME Factor 
   during prediction, preventing 'Data Leakage' and 'Feature Mismatch'.

Q4: "What happens if I give your tool a CSV with 50% missing values?"

A: The 'DataProcessor' (mlcli/core/data.py) detects this using 'missing_percentage' 
   calculations. Our 'Data Quality Issues' engine highlights 'high_missing_columns' 
   as a Warning. We handle the actual missing data using 'SimpleImputer' with 
   configurable strategies (mean/median/constant) defined in the 'mlcli.yaml' config.

--------------------------------------------------------------------------------
PART 3: THE MODELING & AI SUGGESTIONS ENGINE
--------------------------------------------------------------------------------

Q5: "How do you select the 'Best Model'? Is it just a lucky guess?"

A: No. We use 'ModelTrainer' with 'GridSearchCV' (mlcli/core/models.py). We 
   perform Cross-Validation (default 5-folds). This means we split the training 
   data multiple times to ensure the model's accuracy is stable and not just 
   overfitting to a specific subset of data. The model with the highest 
   Cross-Validation score is crowned the 'Best Model'.

Q6: "Your 'suggest' command feels like magic. What is the logic behind it?"

A: It's an 'AI-Guided' rule engine. It analyzes three artifacts:
   1. The Data Profile (for cardinality and size issues).
   2. The Training Summary (for performance gaps).
   3. The Evaluation Report (for precision/recall imbalances).
   If it sees a large gap between precision and recall, it programmatically 
   recommends SMOTE or Class Weighting. If the dataset is under 100 rows, it 
   flags 'Data Insufficiency'.

PART 4: FUTURE SCALABILITY (PHASE 2)
--------------------------------------------------------------------------------

Q7: "A CLI is nice, but how do I get this model into a real Production Cloud?"

A: That is our Phase 2. We will use 'BentoML'. It converts the Scikit-Learn 
   '.pkl' file into a Dockerized API service. This allows the model to be 
   deployed as a 'Microservice' that any website or mobile app can call via HTTP.
